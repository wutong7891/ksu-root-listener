# KSU 前台与输入数字监听 Root 控制台（内测版）

此模块有两种互斥模式：未设置激活数字时完全采用 v11，指定应用进入前台便以 Root 执行一次 Shell，且不调用 UIAutomator；设置数字后，当前普通输入框精确匹配时立即执行，无需回车或收起键盘。

模块仓库自带 `.github/workflows/build-module.yml`。正式构建通过 GitHub Actions 完成，包括元数据校验、Shell 语法检查、ShellCheck、ZIP 完整性验证和 Artifact 上传。

## 运行方式

- KernelSU 在开机的 `late_start service` 阶段执行模块的 `service.sh`。
- `service.sh` 启动独立监听进程，不依赖 KernelSU 管理器 App 常驻后台。
- 管理器被划掉或强制停止后，已经启动的模块监听仍会运行。
- 轮询 Android 当前前台应用和输入法可见状态；打开应用本身不会执行。
- 设置数字时通过 Root UIAutomator 仅核对当前焦点普通输入框是否等于配置数字，不记录实际输入。
- 留空时完全跳过 UIAutomator，按 v11 的应用进入前台事件执行一次。
- 数字模式会先尝试内存输出；ROM 不兼容时自动切换为模块私有临时 XML，读取后立即删除。
- WebUI 的“检测当前输入”会报告是否匹配，或明确报告 UIAutomator 不可用。
- Root 守护器会在监听器意外退出后自动拉起，保存启用配置时也会检查并启动服务。
- 启用后约每 0.25 秒发现目标应用；进入目标应用后约每 0.10 秒发起输入检查。
- 保存配置或升级安装时会结束旧版监听进程并加载当前版本，不再必须重启手机。
- 内容匹配后立即执行；同一内容保持不变时只执行一次，改掉或清空后重新输入才允许再次触发。
- 目标应用位于后台时不触发，Root 请求也不会触发脚本。
- 监听器使用原子单实例锁，避免两个后台监听进程造成顺序重复执行。
- 提供脚本预输入台；每一行作为一次输入并附加回车，自动送入脚本标准输入。
- 数字匹配后，以 Root 身份、从 `/` 目录立即执行指定 Shell 文件。

## 必要条件

需要 KernelSU 能正常运行模块的 `service.sh`。不需要 `sulog`，也不启用或读取 Root 事件日志。

## 安装与配置

1. 从 GitHub Actions 下载并在 KernelSU 管理器安装构建出的模块 ZIP。
2. 重启手机，使模块的 `service.sh` 自动启动。
3. 打开模块 WebUI，填写目标应用包名与 Shell 文件绝对路径。
4. 开启“启用监听”并保存配置。激活数字留空使用 v11 前台触发；填写数字则使用输入匹配触发。
5. 点击“打开应用”或从桌面进入目标应用。空数字模式会立即执行；数字模式在普通输入框完整匹配时执行，无需回车。

## 脚本预输入台

如果脚本会依次要求输入菜单数字、文字和确认内容，可在 WebUI 中逐行填写，例如：

```text
1
测试文字
y
```

模块执行时等效于依次输入 `1`、`测试文字`、`y`，每项后按一次回车。自动监听触发与手动执行共用同一份预输入配置。该功能适用于从标准输入读取内容的 Shell 脚本；需要真实 TTY、方向键或密码遮罩的交互程序不保证兼容。

## 脚本环境变量

触发脚本可以读取：

- 空数字模式：`KSU_TRIGGER_TYPE=app_foreground`
- 数字模式：`KSU_TRIGGER_TYPE=input_match`
- `KSU_TRIGGER_PACKAGE`：配置的目标包名。

## 日志

- 模块触发日志：`/data/adb/ksu_app_watcher/logs/trigger.log`
- 持久化配置：`/data/adb/ksu_app_watcher/config/`

## 安全说明

Root 控制台和触发脚本拥有不受限制的 Root 权限。请只选择和执行你完全信任的文件。模块只比较目标应用当前焦点输入框是否与本地配置值相同，不记录实际输入，不检查密码框，不安装无障碍服务，也不需要管理器 App 保持在后台。WebView、游戏自绘输入框或未向 UIAutomator 暴露文本的界面无法使用此验证。
